# 故障排查

## Web 控制台打不开

### 直连热点

1. 确认连接的是 `Robot`。
2. 默认密码为 `12345678`。
3. 即使系统提示“无 Internet”，也要保持连接。
4. 地址必须是 `http://192.168.4.1`，不要使用 `https`。
5. 暂时关闭移动数据自动切换或 VPN。

### STA 局域网

1. 确认电脑与驱动板在同一个路由器网络。
2. 查看 OLED 上的 STA IP。
3. IP 可能因路由器 DHCP 重新分配而变化。
4. 尝试从路由器管理页面查找设备。

## 页面打开但按钮无响应

- 查看 `Uptime` 是否每秒更新。
- 刷新页面。
- 关闭重复打开的控制页面。
- 检查网络信号。
- 重启驱动板。

## 舵机不转

1. 是否接入外部动力电源。
2. 电源开关是否为 `ON`。
3. 电压是否匹配舵机。
4. 是否选择正确的舵机系列组件。
5. 总线波特率是否匹配。
6. ID 是否正确或冲突。
7. 单独连接一个舵机，使用广播 ID `254` 测试。
8. HLS 指令中的速度是否为有效非零值。

## 修改 ID 后无法控制

- 设置 ID 时总线上是否连接了多个同 ID 舵机。
- 先只连接一个舵机。
- 使用广播 ID `254` 尝试重新设置。
- 修改后用新 ID 发送一条明显不同位置的动作。

## USB CDC 没有端口

=== "Windows"

    - 检查是否连接了标有 `USB` 的原生 USB 接口。
    - 打开设备管理器，连接前后对比新增 COM 端口。
    - 更换支持数据传输的 Type-C 线。

=== "macOS"

    ```bash
    ls /dev/tty.usbmodem* /dev/cu.usbmodem*
    ```

=== "Linux"

    ```bash
    ls /dev/ttyACM* /dev/ttyUSB*
    dmesg | tail
    ```

## Python 提示端口被占用

关闭：

- YAT
- `screen`
- PlatformIO Serial Monitor
- Arduino Serial Monitor
- 其他正在运行的 Python 脚本

## HTTP 连接失败

| 错误 | 处理 |
| --- | --- |
| `ConnectionError` | 检查 IP、Wi-Fi 和驱动板电源 |
| `Timeout` | 检查网络信号、防火墙和设备是否卡死 |
| `404` | 使用 `/api/cmd`，确认固件支持 HTTP |
| `400` | 检查 JSON 是否有效、请求头是否为 JSON |

## WebSocket 连接失败

地址格式必须为：

```text
ws://<设备 IP>:80/ws
```

如果提示缺少模块：

```bash
pip install websocket-client
```

如果连接后收不到数据，确认固件是否主动上报状态；没有状态上报并不代表连接失败。

## FD 软件无法控制舵机

1. 电脑连接的是驱动板 `UART` 接口。
2. FD 软件端波特率选择 `1M`。
3. UART0 透传已开启：`{"T":605,"sf":1}`。
4. 驱动板到舵机的波特率已用 `T:10` 设置正确。
5. 外部电源和开关正常。

## UART JSON 指令无响应

UART0 默认用于透传。先通过其他通道发送：

```json
{"T":605,"sf":0}
```

然后确保 UART 使用 1 Mbps、每条 JSON 以换行结尾，并且 TX/RX 交叉连接、共地。

## Wi-Fi 或 ESP-NOW 配置异常

先尝试清理 NVS：

```json
{"T":601}
```

设备重启后重新配置网络。

## 任务无法运行

- 每条 JSON 是否独占一行。
- JSON 是否有缺少引号、逗号或大括号。
- 任务名称是否省略 `.mission` 后缀。
- 是否有另一个无限循环任务正在运行。
- 先发送 `{"T":0}` 停止当前任务。
