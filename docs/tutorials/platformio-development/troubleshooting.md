# PlatformIO 常见问题

## PlatformIO 一直初始化

1. 完全退出 VS Code。
2. 重新打开并等待 Core 安装。
3. 检查磁盘空间和网络。
4. 不要同时安装多个 PlatformIO IDE 扩展。
5. 从 PlatformIO 终端运行 `pio --version`。

## 普通终端找不到 pio

PlatformIO 扩展可能只在自己的终端中配置环境。优先：

- 使用 VS Code 状态栏按钮
- 使用 `PlatformIO: New Terminal`
- 不要另外安装来源不明的同名命令

## 打开项目后没有编译按钮

检查：

- 打开的是否是包含 `platformio.ini` 的目录
- PlatformIO 扩展是否启用
- VS Code 是否处于受限模式
- `platformio.ini` 是否存在语法错误

## 第一次构建下载失败

平台、工具链和库需要联网下载。保留完整日志，区分：

- DNS 或连接超时
- 仓库不可访问
- 磁盘权限
- 包版本不存在

不要通过反复删除配置来掩盖网络问题。

## 找不到头文件

典型错误：

```text
fatal error: SomeLibrary.h: No such file or directory
```

处理：

1. 确认依赖写在 `lib_deps`。
2. 检查头文件名称大小写。
3. 检查库版本是否提供该文件。
4. 清理并重建。

```bash
pio run -t clean
pio run
```

## 链接阶段重复定义

常见原因：

- 同一函数在头文件中被多次定义
- 同一个库同时存在于 `lib/` 和 `lib_deps`
- 全局变量在头文件中直接定义

头文件中使用 `extern` 声明，全局变量只在一个 `.cpp` 中定义。

## 找不到上传端口

1. 确认 USB 线支持数据。
2. 对比插拔前后的端口列表。
3. 关闭串口监视器。
4. 确认使用正确的 USB/UART 接口。
5. 必要时手动进入下载模式。

查看端口：

```bash
pio device list
```

## 上传时 Access denied / Permission denied

=== "Windows"

    关闭串口终端、设备调试工具和其他 VS Code 窗口。确认 COM 端口没有被占用。

=== "Linux"

    查看端口权限，并按照发行版方式将当前用户加入串口设备组。注销并重新登录后生效。

=== "macOS"

    关闭占用 `/dev/cu.*` 的程序，重新插拔设备并确认端口名称。

## 一直等待 Connecting

- 按住 BOOT/IO0，短按 RESET/EN，再松开 BOOT
- 降低上传速度
- 断开可能干扰启动引脚的外设
- 确认开发板配置和芯片型号正确

## 上传成功但程序不运行

检查：

- 串口监视器波特率
- 是否反复复位
- 分区表是否匹配
- Flash/PSRAM 配置是否正确
- 程序是否在等待网络或外设
- 是否把文件系统内容误当作程序上传

在 `setup()` 最开始增加最小日志或 LED 指示。

## 修改网页后没有变化

如果网页位于 `data/`，需要上传文件系统：

```bash
pio run -t uploadfs
```

随后清除浏览器缓存或强制刷新。确认固件挂载的文件系统类型与 `platformio.ini` 一致。

## 修改代码后行为没有变化

确认：

- 保存了文件
- 构建的是正确环境
- 上传到了正确设备
- 没有多个同名源文件
- 实际运行的不是旧的出厂镜像

构建前执行：

```bash
pio run -t clean
```

## 固件体积超限

- 检查是否选错分区表
- 删除未使用功能和资源
- 避免重复包含大型静态数据
- 检查调试符号和日志
- 不要随意扩大程序分区而压缩用户数据空间

## 运行时崩溃或看门狗复位

1. 保存完整启动和异常日志。
2. 启用适合平台的异常解码过滤器。
3. 检查数组越界、空指针和栈空间。
4. 检查循环中长时间阻塞。
5. 逐个关闭最近新增模块。
6. 回到最近一次可工作的 Git 提交比较。

## 机器人动作异常

立即断开动力电源，然后检查：

- 引脚和设备 ID
- 总线波特率
- 关节方向与限位
- 默认任务和开机动作
- 配置文件是否被旧版本覆盖
- 通信超时和 failsafe

!!! danger "不要靠反复上电试错"
    运动方向、限位或控制周期不确定时，应先用无负载、低速度、单关节或模拟输出验证。

## 提问时应提供

- 操作系统
- 开发板和芯片
- PlatformIO 环境名
- 完整 `platformio.ini`
- 第一条错误及其前后日志
- 使用的 USB 接口和端口
- 原始项目是否能编译
- 修改了哪些文件
